# 機能要件書 — RaiseChat

関連: [要件定義書](requirements.md) / [「Slack 風」の捉え方](why-slack.md)

## 2. 機能詳細（機能定義）

### F-01 ユーザー認証機能

**ユーザー登録**

- 入力: ユーザー ID（半角英数 + 一部記号、一意）、表示名、パスワード
- バリデーション:
  - ユーザー ID は 3〜32 文字、半角英数 + `_` / `-`、重複不可
  - 表示名は 1〜32 文字
  - パスワードは 8 文字以上、英字・数字を両方含むこと
- パスワードは Bcrypt でハッシュ化して保存
- **メール認証は実装しない**（要件によりスコープ外）
- 登録成功後、ログイン画面へ遷移

**ログイン**

- 入力: ユーザー ID、パスワード
- 認証成功: JWT アクセストークン（短期）+ リフレッシュトークン（長期）を発行
- 認証失敗: 「ユーザー ID またはパスワードが正しくありません」を表示
- 未ログイン状態で保護領域にアクセスした場合はログイン画面へリダイレクト

**ログアウト**

- クライアント側でトークンを破棄
- サーバー側でリフレッシュトークンを失効

**関連エンドポイント（仮）**

- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/refresh`
- `POST /api/auth/logout`

---

### F-02 プロフィール管理機能

**プロフィール表示**

- アバター画像・表示名・ステータスメッセージ・ユーザー ID を表示

**プロフィール編集**

- 自分のアバター画像・表示名・ステータスメッセージを編集可能
- バリデーション:
  - 表示名: 1〜32 文字
  - ステータスメッセージ: 0〜100 文字
  - アバター画像: JPEG / PNG / GIF、最大 2MB
- アバター画像は AWS S3 に保存し、URL を DB に保持

**関連エンドポイント（仮）**

- `GET /api/users/me`
- `PUT /api/users/me`
- `POST /api/users/me/avatar`

---

### F-03 ワークスペース管理機能

**ワークスペース作成**

- 任意のログイン済みユーザーが新規ワークスペースを作成可能
- 入力: ワークスペース名（1〜64 文字、必須）、説明（0〜255 文字、任意）
- 作成者は自動的に **オーナー権限** を持つ
- 作成時に既定のチャンネル `general` を自動作成する

**ワークスペース参加**

- 招待リンク（F-15）または管理者からの招待で参加
- 参加後、ワークスペース内のパブリックチャンネルが閲覧可能になる

**ワークスペース切り替え**

- 複数ワークスペースに所属している場合、サイドバーから切り替え可能

**関連エンドポイント（仮）**

- `POST /api/workspaces`
- `GET /api/workspaces` (自分が所属するワークスペース一覧)
- `GET /api/workspaces/{id}`

---

### F-04 チャンネル管理機能

**チャンネル作成**

- ワークスペースに所属するユーザーが作成可能
- 入力: チャンネル名（1〜80 文字、ワークスペース内で一意）、説明（0〜255 文字、任意）、種別（パブリック / プライベート）
- パブリックチャンネルはワークスペース全員が閲覧・参加可能
- プライベートチャンネルは招待された人のみ閲覧・参加可能

**チャンネル参加 / 退出**

- パブリックチャンネル: 自由に参加・退出可能
- プライベートチャンネル: 既存メンバーから招待されたユーザーのみ参加可能、自由に退出可能

**チャンネル削除**

- オーナーまたはチャンネル作成者のみ削除可能（F-16）

**関連エンドポイント（仮）**

- `POST /api/workspaces/{wsId}/channels`
- `GET /api/workspaces/{wsId}/channels`
- `POST /api/channels/{id}/join`
- `POST /api/channels/{id}/leave`
- `DELETE /api/channels/{id}`

---

### F-05 チャンネルメッセージ機能（中核）

**メッセージ送信**

- チャンネルに所属するユーザーがテキストメッセージを送信できる
- 入力: テキスト（1〜4000 文字、必須）、添付ファイル（任意、F-10）
- 送信は WebSocket（STOMP）経由でサーバーに到達し、チャンネル所属メンバー全員にプッシュ配信される
- 送信成功時、送信者の画面にも即座に反映される

**メッセージ取得（履歴）**

- チャンネルを開いた時に直近 N 件のメッセージを取得
- 過去メッセージは無限スクロール（カーソルベースページネーション）で追加読込
- 直近メッセージはキャッシュ層（Redis）から優先取得（非機能要件）

**リアルタイム配信**

- バックエンドが複数インスタンスでも、ワークスペース内全クライアントへブロードキャストされる
- 配信の遅延は **1 秒以内** を目標（非機能要件）

**関連エンドポイント / WebSocket destination（仮）**

- `GET /api/channels/{id}/messages?cursor=...`
- WebSocket subscribe: `/topic/channels/{id}`
- WebSocket send: `/app/channels/{id}/messages`

---

### F-06 ダイレクトメッセージ機能

**DM 開始**

- 同一ワークスペースに所属する任意のユーザーと 1 対 1 で DM を開始できる
- 既に DM ルームがある場合は既存ルームを開く（重複作成しない）

**DM 送信・取得**

- F-05 と同様の入力ルール（テキスト 1〜4000 文字、添付対応）
- WebSocket でリアルタイム配信される
- DM はワークスペース外には漏れない

**関連エンドポイント / WebSocket destination（仮）**

- `POST /api/dm/rooms` (相手ユーザー ID を指定)
- `GET /api/dm/rooms/{id}/messages?cursor=...`
- WebSocket subscribe: `/topic/dm/{roomId}`
- WebSocket send: `/app/dm/{roomId}/messages`

---

### F-07 メッセージ編集・削除機能

**メッセージ編集**

- 自分のメッセージのみ編集可能
- 編集後、メッセージに「(編集済み)」マークを付与
- 編集イベントは WebSocket でチャンネル全員にプッシュ配信される

**メッセージ削除**

- 自分のメッセージは削除可能
- オーナーは他人のメッセージも削除可能（F-16）
- 削除確認ダイアログを表示してから削除
- 削除イベントは WebSocket でチャンネル全員にプッシュ配信される
- 関連スレッド・リアクション・添付ファイルもまとめて論理削除する

**関連エンドポイント（仮）**

- `PUT /api/messages/{id}`
- `DELETE /api/messages/{id}`

---

### F-08 スレッド機能

**スレッド開始**

- 任意のチャンネルメッセージ / DM メッセージに対して **返信** することでスレッドが開始される
- 親メッセージにスレッド数バッジが表示される

**スレッドビュー**

- メッセージをクリックすると右ペインに独立したスレッドビューが開く
- スレッド内でも F-05〜F-07 と同じ操作（送信・編集・削除・リアクション・メンション）が可能
- スレッド返信はメインチャンネルには流れず、スレッド内に閉じる

**関連エンドポイント / WebSocket destination（仮）**

- `GET /api/messages/{parentId}/replies?cursor=...`
- `POST /api/messages/{parentId}/replies`
- WebSocket subscribe: `/topic/threads/{parentId}`

---

### F-09 マークダウン記法対応

**対応記法**

- 太字（`**text**`）/ 斜体（`*text*`）
- インラインコード（`` `code` ``）/ コードブロック（``` ```lang``` ```）
- リスト（`-` / `1.`）
- 引用（`>`）
- リンク（`[text](url)`）

**安全性**

- マークダウンレンダリング時に **HTML エスケープ**して XSS を防ぐ
- 許可しないタグ・属性は除去

---

### F-10 ファイル添付機能

**ファイルアップロード**

- メッセージ送信時に画像・動画ファイルを添付可能（任意・複数添付）
- 対応形式: JPEG / PNG / GIF / WEBP / MP4
- 最大ファイルサイズ: 10MB / 件
- バリデーション: ファイル形式（MIME type） / ファイルサイズ

**ファイル保存**

- アップロードされたファイルは AWS S3 に保存
- DB にはファイルメタデータ（URL / MIME / サイズ / 元ファイル名）を保存

**ファイル表示**

- 画像はサムネイル表示、クリックで原寸表示
- 動画はインラインプレイヤーで再生

**関連エンドポイント（仮）**

- `POST /api/attachments`
- `GET /api/attachments/{id}`

---

### F-11 絵文字リアクション機能

**リアクション追加 / 解除**

- 任意のメッセージに対して標準絵文字でリアクションを付与できる
- 同一ユーザー・同一絵文字での重複付与は不可
- リアクション解除も可能

**リアクション表示**

- メッセージ下に絵文字とカウントを表示
- リアクションを付けたユーザー一覧がツールチップで表示される
- リアクションの追加・解除イベントは WebSocket でチャンネル全員にプッシュ配信される

**関連エンドポイント / WebSocket destination（仮）**

- `POST /api/messages/{id}/reactions`
- `DELETE /api/messages/{id}/reactions/{emoji}`

---

### F-12 メンション機能

**メンション入力**

- メッセージ本文に `@<ユーザーID>` を含めるとそのユーザーへのメンションとなる
- 入力中にサジェスト UI を表示（同チャンネル参加ユーザーから補完）

**メンション表示**

- メンション部分はハイライト表示され、メンションされたユーザーへの通知（F-14）が発火する

**特殊メンション**

- `@channel` / `@here` は本 MVP では実装しない（後続検討）

---

### F-13 メッセージ検索機能

**検索範囲**

- 自分が所属するワークスペース内の閲覧可能なチャンネル・DM のメッセージ全文
- プライベートチャンネル / DM のうち自分が所属していないものは検索対象外

**検索 UI**

- 上部の検索バーにキーワードを入力
- 検索結果: メッセージ本文 / 投稿者 / チャンネル名 / 投稿日時を一覧表示
- 結果クリックで該当メッセージへジャンプ

**フィルタ**

- チャンネル指定 / 投稿者指定 / 期間指定（後続実装でも可、MVP では最低限キーワード検索）

**関連エンドポイント（仮）**

- `GET /api/search?q=...&workspaceId=...&channelId=...&from=...`

---

### F-14 通知機能

**未読カウント**

- 各チャンネル / DM ごとに未読メッセージ数をサイドバーに表示
- 既読時に自動的にゼロクリア
- 未読カウントは Redis でキャッシュし、高頻度更新に耐える（非機能要件）

**メンション通知**

- メンションされた場合、サイドバーのチャンネル名にメンションバッジを付与
- ブラウザ通知（Notifications API）でも知らせる（任意で有効化）

**関連エンドポイント / WebSocket destination（仮）**

- `GET /api/notifications/unread`
- `POST /api/channels/{id}/read`
- WebSocket subscribe: `/user/queue/notifications`

---

### F-15 招待機能

**ワークスペース招待**

- オーナーが招待リンク（ワンタイムまたは期限付き）を発行
- 招待リンクからサインアップ or 既存ユーザーログイン経由でワークスペースに参加できる

**チャンネル招待**

- パブリックチャンネル: 招待不要、各自で参加可能
- プライベートチャンネル: 既存メンバーが他ユーザーを招待

**関連エンドポイント（仮）**

- `POST /api/workspaces/{id}/invites`
- `POST /api/channels/{id}/invites`
- `POST /api/invites/{token}/accept`

---

### F-16 管理者操作機能

**ユーザーキック**

- オーナーがワークスペースから任意のメンバーを強制退出できる
- キックされたユーザーは即座にワークスペース内のチャンネル・DM へアクセス不能になる

**チャンネル削除**

- オーナーまたは作成者のみがチャンネルを削除可能
- 削除時、紐づくメッセージ・リアクション・添付も論理削除

**ワークスペース削除**

- オーナーのみ可能（要確認モーダル）

**関連エンドポイント（仮）**

- `DELETE /api/workspaces/{wsId}/members/{userId}`
- `DELETE /api/channels/{id}`
- `DELETE /api/workspaces/{id}`

## 3. ユースケース

### UC-01: 新規ユーザーがワークスペースを作って業務チャットを始める

1. ユーザーが新規登録画面でユーザー ID・表示名・パスワードを入力する（F-01）
2. ログイン後、ワークスペース新規作成画面でワークスペース名を入力する（F-03）
3. 自動作成された `general` チャンネルにメッセージを投稿する（F-04, F-05）
4. プロフィールにアバター画像と表示名を設定する（F-02）

### UC-02: 招待されたメンバーがワークスペースに参加して会話に加わる

1. オーナーから招待リンクを受け取る（F-15）
2. 招待リンクからログインしてワークスペースに参加する（F-03）
3. パブリックチャンネル `#dev-backend` に参加し、過去メッセージをスクロールで遡る（F-04, F-05）
4. 直近の議論にリアクション 👍 を付ける（F-11）

### UC-03: スレッドで個別議論を分岐させる

1. メインチャンネルで「ログイン処理を直したい」と投稿される（F-05）
2. メンバーがそのメッセージへの返信としてスレッドを開く（F-08）
3. スレッド内で具体的な実装方針を議論し、メインの流れを汚さない（F-08）
4. スレッド内で `@user` でレビュー依頼を送る（F-12, F-14）

### UC-04: 過去の議論を検索して参照する

1. ユーザーが検索バーに「リフレッシュトークン」と入力する（F-13）
2. 結果一覧から該当メッセージへジャンプする（F-13）
3. その時のスレッドを開いて議論の経緯を確認する（F-08）

### UC-05: 自分のメッセージの誤りを編集・削除する

1. メッセージを送信した後、誤字に気付く（F-05）
2. 編集機能で本文を修正し「(編集済み)」マークが付く（F-07）
3. 完全に不要なメッセージは削除する（F-07）

### UC-06: DM で 1 対 1 の相談をする

1. メンバー一覧から相手を選び DM を開始する（F-06）
2. DM チャンネルで相談メッセージを送る（F-06）
3. 相手が画像ファイルを添付して返信する（F-06, F-10）

### UC-07: オーナーがメンバーを管理する

1. オーナーがプライベートチャンネルを作成し、特定メンバーのみ招待する（F-04, F-15）
2. 退職したメンバーをワークスペースからキックする（F-16）
3. 不要になったチャンネルを削除する（F-16）

### UC-08: 未読・メンションを確認して取りこぼしを防ぐ

1. ユーザーがログインするとサイドバーに未読バッジが表示される（F-14）
2. メンションされたチャンネルを優先して開き、議論を確認する（F-12, F-14）
3. メッセージを読むと未読カウントが自動でクリアされる（F-14）
